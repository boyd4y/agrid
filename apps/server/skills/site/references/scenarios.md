# 按场景安排页面和数据

## 品牌表单与问卷

围绕填写者设计短表、分步或一题一屏，使用自定义文案、排版和组件。问题对应已有可写列；满意度可用 number 或 select，选项使用真实 option ID。条件显隐可在页面实现，但它不提供服务端业务校验。提交表只需新增权限，禁止读取其他人的回答。

必填、长度、分支约束等页面规则尚不会自动同步到数据 API；当前 API 校验字段类型和权限。若用户要求这些规则不可绕过，需要补服务端提交规则，不能仅靠 HTML 属性或 JavaScript 声称已保障。文件上传目前需要登录工作区，不能在公开问卷里承诺上传成功。

## 活动报名

页面展示活动介绍、地点、时间和报名表。活动内容表只读，报名表仅新增，两者使用同一普通 API Key 的独立授权。提交后通过表格 row_created 接后续工作；不要为了收到报名就再建一套后台。

名额显示不等于锁定名额，浏览器查重不等于唯一约束。硬性限额、幂等提交、同一邮箱只报一次需要服务端事务或数据库约束；支付、邮件发送和登录后修改报名也需要实际可用的对应能力。普通报名页不要擅自加入这些流程。

## 知识与资源分享

任何表都可作为站点视图的来源表；博客只是展示模板。标题、分类等映射到普通列，文章内容使用记录内置 body 字段，资源仅包含明确选中的图片。页面可提供列表、搜索、分页和详情。带 Key 的文件链接沿用数据 API 返回的 URL。内部草稿不与公开内容放在同一授权表；前端按状态隐藏草稿不会阻止访客读取它。

正文默认按文本呈现。需要 Markdown 或富文本时复用项目内可用且经过安全处理的渲染器，避免把脚本、事件属性或不可信链接作为文章 HTML 执行。反馈另存仅新增表。

## 产品目录与咨询

公开产品或服务表只读，咨询表仅新增。详情页面传真实项目 ID，咨询表如需保存该 ID 可使用明确的 text 列；当前数据 API 不支持写 relation 字段，不能直接提交关联对象。图片和附件使用真实记录返回的文件元数据。

## 简单门户

组合公告、资源、活动和收集入口，按访客任务组织导航。公开门户可以复用上述只读/仅新增模式。当前 API Key 的权限覆盖整张表，不能实现「每个用户只看自己的订单或申请」；这类个人门户需要登录和行级授权后再承诺交付。

## 修改已有网站

先读取页面文件和实际表结构，保留现有字段 UUID 和数据。文案或样式调整不应重建表格；字段改名后刷新元数据而非猜测新 ID。未明确要求发布时，修改源文件并报告验证结果，不改变正在使用的公开网站。
