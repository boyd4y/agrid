# 用页面连接真实业务

适用于需要自由设计页面和交互、同时把内容或提交保存到表格的任务。输出是保存在平台中的 HTML/CSS/JS 站点版本、真实字段绑定、可查看的预览及已验证的行为。技能可供现有智能体按需使用，也可由用户分配给专门建站的智能体；不要求创建新的 Agent、服务或运行循环。只需要平台内表单视图时使用 form。

## 从场景到页面

先确定访客需要看到什么、完成什么操作，以及提交后团队如何处理。按需阅读 [references/scenarios.md](references/scenarios.md)，用用户的品牌、文案和内容设计页面，不把表格全部字段机械地铺到页面上。需求明确时直接推进；没有说明的低风险视觉细节自行选择。

用实际可用的 list_tables、get_table 读取表格和字段 UUID，缺少结构时配合 table 技能补齐。区分公开内容和收集数据：内容表一般只读，报名或反馈表一般仅新增。浏览器筛选不是数据权限，不能用一个只读 Key 暴露含内部资料的整张表。

已有站点先 list_sites / get_site；修改前读取最新 version 和文件，get_site 可按 path 读取单个文件。用 Harness 原生文件工具生成或修改实际文件，随后调用 save_site 把完整文件集保存到平台。新建传 name/files，修改另传 siteId/expectedVersion；files 会整体替换，不遗漏原有资源。SDK是独立发布的npm包，纯HTML页面直接导入当前部署提供的固定CDN地址，不复制SDK源码或创建本地tabdo.js。沿用已有项目结构，没有项目时可从 index.html、styles.css、app.js 开始。普通静态页面不需要长驻 Agent 或额外后端。保留用户已有内容和文件，增量修改。组件库、构建方式和资源来源以当前项目为准；日期、时间、下拉选择等交互沿用项目的自定义控件风格，避免弹出浏览器原生选择器。

## 接入数据

阅读 [references/data-api.md](references/data-api.md) 后接入现有 SDK 或 GraphQL。Key 统一在「设置 → API Key」配置，逐表选择读取、新增、更新、删除；不另造站点凭证或要求数据库连接。管理权限及未提供的授权工具不能通过智能体身份绕过。未取得有效配置时仍可完成页面，将待配置项集中列出，不把占位 ID 或模拟提交称为真实联动。

按真实列类型编码值，选项传 option ID，拒绝无效数字和日期。用户输入、表格文本和外部内容按文本渲染，不直接插入 HTML。报名失败保留填写内容；阻止提交期间重复点击，成功后再显示完成状态。不要把请求已发出、超时或页面跳转当作写入成功，也不要自动重试结果不确定的新增请求。

## 验收与交付

核对页面窄屏布局、键盘操作、空内容、加载、提交成功和失败状态。有实际浏览器工具时打开真实页面验收；只检查源码或 HTTP 响应时说明尚未完成浏览器验收。需要验证提交时使用可识别的测试内容，通过管理侧读取确认目标表新增的值；仅新增 Key 不能读取历史记录。只清理本次测试数据。

save_site 成功后调用 open_preview(kind=site,siteId)，打开站点真实预览；用户可在站点编辑器查看文件、修改代码、连接 API Key、保存版本及恢复历史。用户要求发布时，用 get_site 核对 revisionId 后调用 publish_site；以成功返回的 publicUrl 为准。发布失败保留原版本，保存不会改变已发布内容。撤下用 unpublish_site，不能把工作区文件、本地监听地址或预览链接称为已发布网站。交付时列明版本、真实验收结果、尚未配置的数据项和实际发布状态。

需要报名后的持续整理或通知时配合 automation；读取收集结果和生成统计时配合 report。页面本身只调用数据 API，不让每次访客访问触发智能体。
