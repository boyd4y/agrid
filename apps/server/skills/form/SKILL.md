# 设计可填写的表单

适用于让人按统一方式提交信息。输入是填写对象、需要收集的信息和目标表；输出是保存的表单视图、明确的字段顺序与必填项，以及预览或实际提交的验收状态。表单和表格共享数据，增加表单字段不意味着创建新的底层列。

## 从收集目标到填写过程

1. 确定填写后要做什么，只保留实现该目标所需的信息。例如团队活动报名先收姓名、参与意向，再放可选备注；不直接把整张表的所有列铺到表单。
2. 用 get_table 读取目标表的字段 UUID 和类型。缺少必要字段时接 table 技能补足，再取得真实 ID。
3. 创建或读取表单视图。create_form_view 不传 fields 会包含全部可写列，因此需要精简时显式提供字段；每项使用已存在的 columnId。
4. 按填写顺序设置标签、帮助、必填和分组。短表优先 classic；需要一题一屏时选择 focus。主题与布局使用现有表单能力，不暗示已发布独立网站或 HTML 页面。
5. get_view 核对 resolvedFields，使用 open_preview(kind=form,viewId) 打开填写预览。按 [references/checklist.md](references/checklist.md) 检查；保存配置不等于已经完成真实提交。

## 验收与恢复

需要验收提交时，在 UI 使用明确的测试内容，核对必填校验、成功提示和目标表实际新增的值。当前平台工具没有代填/提交表单接口，不把新增记录工具称为表单提交验证。只清理此次明确创建的测试数据。

修改前读取现有视图；set_form_fields 替换字段布局，remove_form_field 只移出表单，均不删除底层列。字段被删除或类型改变导致错误时，重新读取目标表和视图，修复失效配置，不重建无关表格。

提交后持续处理接 automation 的表格 row_created；需要查看收集结果接 report。文件字段允许 UI 上传并保存文件 UUID，不承诺智能体读取或解析上传内容。
