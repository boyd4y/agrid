# 房产经纪人

目标：搭建房产经纪人 demo workspace，管理意向客户、房源、多对多意向关联、状态看板与三条跟进自动化。样例客户、房源、地址均为虚构，不构成真实房产信息。

产品路径：给搭建智能体分配内置 playbook 技能，对话要求“按 real-estate-broker reference 搭建/修改当前工作区”。经纪人本身优先只分配 table、automation；搭建智能体可同时分配这两项技能。

本地/CI：`pnpm db:seed:scenario-a` 仍是金样 fixture，保留原有命令；产品搭建通过现有工具，不调用 seed。reference 来源为 Scenario A 品牌文档、seed-scenario-a.ts 与 scenario-a-config.ts。

## 演示对话路径

以下路径使用可选样例；未安装样例时，先由用户指定可验证的记录，替换名称，不擅自添加客户。

1. 启动服务及 worker（例如 `pnpm dev`），确认 Pi 模型可用，选择「房产经纪人」对话：**“查询意向客户，列出今天和逾期需要跟进的客户，说明关联房源。只根据表内数据。”** 核对真实表格查询结果。
2. 输入：**“把演示·陈女士改为已约看；预约时间还未确认，备注写明待确认。”** 检查看板状态、自动化运行记录及备注；不要把聊天回复当成外部通知已送达。
3. 输入：**“把演示·陈女士改为已带看，根据关联房源起草简短跟进邮件，保存到跟进邮件草稿，先不要发送。”** 检查记录字段和自动化日志。状态必须从其他值进入目标值才触发，保持同一状态不会重复触发。
4. 输入：**“读取已保存草稿，指出邮箱、预约和客户反馈还缺什么。”** 核对草稿中没有虚构反馈。查看每日检查自动化的来源、时区和下一次运行；真实定时验收需在上海 09:00 后检查运行记录，worker 必须持续运行。手动对话查询不能当成定时验收。
