# 验证执行与失败恢复

## 配置验收

list_automations 支持工作区分页，可选 tableId 筛选；工具返回规则数组，按 offset+=limit 继续查询，直到返回长度小于 limit；恰好整页时可再查一次空页。HTTP 列表的 {rules,hasMore} 形状不能套用到工具结果。核对实际 source、trigger、conditions / eventConditions、action 输入与 enabled，保存配置成功不等于发生过事件。

修改规则不能将已保存来源类型或表格来源表换成其他类型/表。需要不同来源时按用户需求创建新规则，并明确旧规则是否仍启用，不默认同时运行两份。

## 引发与观察

- 表格：创建明确测试记录，或产生真实字段新值变化。将字段再次设成当前值不能证明 field_changed；进入状态需要真实切换到该选项。
- Webhook：仅在用户已授权测试发送时，由实际发送方请求已创建 endpoint；不要凭空宣称收到请求。
- 邮件：使用真正进入订阅邮箱的事件。配置连接成功和收件成功是不同验收，不为测试自动发送邮件。
- 定时：核对 cron、时区、显示的下次时间与到期执行；没有等待发生就说明尚未验证真实触发。

list_automation_runs 可按 automationId 查看所有来源的执行，也可按 tableId 查看表格范围；limit 最多200，有限返回不代表全部历史。查看 status、nextStep、error 和 detail 的关联 threadId / agentRunId。已排队期间不要反复改测试记录或重复发送事件。

## 结果与恢复

- completed：核对实际目标数据/原生 Agent 输出，不能只看配置保存提示。
- skipped：事件条件未满足，检查真实 payload 或已补取的邮件正文；不是执行失败。
- waiting_input：打开关联私有对话回答原生问题，等待后续动作状态；不创建新的同任务替代。
- unknown：运行/结果尚不确定，查看原对话及已产生的效果，不盲目重放。
- failed / cancelled / superseded：读取具体原因，检查权限、来源、字段、版本及已完成步骤。superseded 表示触发记录后来已更新，旧事件没有继续覆盖它。

多个动作逐步提交，失败不自动回滚之前成功的步骤；每个 batch command 内部才是整批原子。自动重试与步骤凭据由服务端处理，不能将再次产生同一业务事件当成安全重试。修正规则后测试新事件时避免重复已产生的外部效果。

测试结束仅清理本次明确创建的测试资源，交付规则 ID、验证事件、实际状态、已完成动作与待处理原因。
