# 包边界评审

评审日期：2026-10-15。基线为 `31b0974` 的 core/auth/server 拆分；下文同时记录本轮 queue 修正。部署目标仍为本地和 Railway 的 Node + PostgreSQL + Redis。

## 判断标准

独立包必须拥有可说明、可测试的能力边界。文件数、代码行数和“未来复用”都不能单独证明拆包有价值。检查调用方是否仍直接承担该能力的实现，而不只是检查 import 是否无环。

## Queue：实现下沉不完整，已修正

原包只有 64 行，包含消息接口和 BullMQ 发布封装；Worker、Redis URL/连接策略、延迟处理、失败分类和关闭流程仍在 server。Redis 租约则放在 core。包的名称与拥有的职责不匹配。

本轮归属调整为：

| queue 包拥有 | server 拥有 |
|---|---|
| 消息、投递与失败通知契约 | 自动化消息的字段和版本校验 |
| Redis URL/TLS/认证及生产者/消费者连接策略 | 读取环境变量，选择队列名和运行参数 |
| BullMQ 发布、消费、Worker 锁与 stalled 恢复 | 匹配规则、读取事件、执行数据动作/智能体 |
| 并发设置、暂缓投递、瞬时重试和永久失败 | 根据业务异常决定是否应当重试 |
| Redis 资源租约、续租、所有权检查和释放 | 将工作区/记录映射为资源键和并发组 |
| 排空在途任务、等待失败通知、关闭拥有的连接 | 进程信号、启动多个服务、业务定时扫描 |

server 的生产代码不再导入 BullMQ/ioredis，也不再声明这些直接依赖。架构检查对此增加约束。测试使用报告、缓存等无 Tabdo 依赖的任务验证包本身，再通过 server 队列测试验证业务幂等与故障恢复。

outbox 原子提交、SQL 领取和过期补偿查询保留在业务代码：它们依赖事件状态、generation、Run 和动作收据，不能通过移进 queue 来假装基础设施完整。队列提供至少一次投递，不承诺业务 exactly-once。

## DB：仍然过薄，尚未形成完整的数据包

`packages/db/src/index.ts` 只有 21 行，生产调用方只有 server 的数据库工厂。它拥有连接创建/关闭和泛型类型；schema 分属 auth/server，迁移配置和 SQL 文件仍在 server，事务上下文也在 server。当前命名容易让人误以为它拥有整个平台的数据层。

结论：这只是连接模块，当前独立包的收益有限。不要新增通用 repository/CRUD 层来填充代码。

后续应明确选择一个边界：如果需要独立的应用数据包，应把完整 schema 组装、迁移入口和数据库资源生命周期统一纳入，并说明 auth schema 的归属；如果保持现有 schema/迁移归属，就将这个连接模块收回应用基础设施。不能同时声称“完整 db 包”和“只有驱动工厂”。本轮未借 queue 修正再次移动所有数据模型。

## 其他包

| 包 | 评审结论 |
|---|---|
| `auth` | 保留。拥有 Better Auth 配置、身份 schema、会话/成员校验和 API Key 生命周期；产品智能体权限扩展由 server 注入。 |
| `agent-runtime` | 保留。拥有官方 Harness/Sandbox 组装与文件快照能力；产品 Run/Session、权限、持久化和执行编排已回到 server。 |
| `storage` | 代码虽少，但实际拥有本地与 S3 两种实现及字节流契约，边界比原 queue 完整。需要另行统一本地独占写与 S3 默认覆盖写的语义，不能把接口一致当成行为一致。 |
| `core` | 保留为少量基础服务、错误、摘要、时间计算和共享快照契约。Redis Lua 租约已归 queue；避免继续成为基础设施实现的杂物包。 |
| `shared` | 实际是产品协议和校验，供前端/server/MCP 共用。边界成立；可以在 README 明确含义，无需仅为名称再做一次全仓改名。 |
| `ui` | 组件、主题和设计 token 的边界成立，保留。 |

## Server 内仍需收敛的层次

移除 backend 包解决了跨包业务组织问题，但 `src/commands`、`src/harness` 等入口与 `src/business` 之间仍有较多转发模块。其中显式依赖组装有价值，纯 re-export 和旧平台注释则增加导航成本。后续按业务域逐步合并，保留必要的依赖注入边界，不再为这些转发层新建包。

## 验收边界

queue 修正已通过：完整 `pnpm test` 231 项（包括独立 Redis 合约测试）、测试类型检查、应用隔离队列回归 17 项、完整构建、Docker 构建与生产镜像健康/静态页面/私有接口鉴权检查。队列回归中会主动停止 Redis 的断网项未启用，未操作共享 Redis 生命周期。

PG/Redis 使用隔离测试资源。本地测试不等于 Railway 部署或真实模型/远程 Sandbox 验收。`check:architecture` 能约束依赖方向，不能替代职责和行为评审。
